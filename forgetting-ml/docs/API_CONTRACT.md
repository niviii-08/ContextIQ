# API Contract

Base URL (local dev): `http://localhost:8000`

Interactive docs auto-generated by FastAPI: `/docs` (Swagger UI), `/redoc`.

---

## `GET /health`

Health check / model metadata.

**Response 200**

```json
{
  "status": "ok",
  "model_version": "1.0.0",
  "model_name": "logistic_regression"
}
```

## `POST /api/v1/predictions/forgetting`

Score a single task.

### Request body

```json
{
  "task_id": "Lab Record",
  "task_category": "Academic",
  "priority": "HIGH",
  "location": "Campus",
  "weekday": 2,
  "hour": 14,
  "deadline_distance_hours": 18.0,
  "previous_completion_count": 12,
  "previous_forgetting_count": 8,
  "historical_completion_rate": 0.4,
  "historical_forgetting_rate": 0.55,
  "task_frequency": 0.3,
  "tasks_today": 5,
  "interruptions_today": 4,
  "recent_context_switches": 6,
  "avg_interruption_duration": 8.5,
  "avg_session_duration": 22.0
}
```

### Field reference

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `task_id` | string \| null | optional | passed through into the response as `task` |
| `task_category` | string | one of `Academic, Work, Personal, Health, Household, Social, Finance` | |
| `priority` | string | one of `LOW, MEDIUM, HIGH` | |
| `location` | string | one of `Home, Campus, Office, Commute, Gym, Other` | |
| `weekday` | int | 0–6 (0=Monday) | |
| `hour` | int | 0–23 | |
| `deadline_distance_hours` | float | ≥ 0 | hours until deadline |
| `previous_completion_count` | int | ≥ 0 | |
| `previous_forgetting_count` | int | ≥ 0 | |
| `historical_completion_rate` | float | 0–1 | |
| `historical_forgetting_rate` | float | 0–1 | |
| `task_frequency` | float | 0–1 | |
| `tasks_today` | int | ≥ 0 | |
| `interruptions_today` | int | ≥ 0 | |
| `recent_context_switches` | int | ≥ 0 | |
| `avg_interruption_duration` | float | ≥ 0 | minutes |
| `avg_session_duration` | float | ≥ 0 | minutes |

### Response 200

```json
{
  "task": "Lab Record",
  "prediction_probability": 0.4169,
  "risk_level": "MEDIUM",
  "model_version": "1.0.0",
  "top_features": [
    "Historical completion rate for this user is increasing the estimated forgetting risk",
    "Historical forgetting rate for this user is increasing the estimated forgetting risk",
    "Number of previously completed tasks is increasing the estimated forgetting risk"
  ]
}
```

| Field | Type | Notes |
|---|---|---|
| `task` | string \| null | echoes `task_id` from the request |
| `prediction_probability` | float | calibrated probability in `[0, 1]` |
| `risk_level` | string | `LOW` (<0.33) / `MEDIUM` (0.33–0.66) / `HIGH` (≥0.66) |
| `model_version` | string | semantic version of the served model artifact |
| `top_features` | string[] | natural-language, association-only explanations (never causal claims) |

### Error responses

| Status | Cause |
|---|---|
| 422 | request body fails schema validation (invalid enum value, out-of-range number, missing field) |
| 503 | model artifact not found / not yet trained on the server |

## `POST /api/v1/predictions/forgetting/batch`

Score multiple tasks in one call.

### Request body

```json
{
  "tasks": [
    { "...": "same shape as single-prediction request" },
    { "...": "..." }
  ]
}
```

### Response 200

```json
{
  "predictions": [
    { "...": "same shape as single-prediction response" },
    { "...": "..." }
  ]
}
```

`predictions` is returned in the same order as the input `tasks` list.
An empty `tasks` list returns `{"predictions": []}`.

## Versioning

- `model_version` follows semantic versioning and is embedded in every
  prediction response, sourced directly from the trained artifact
  (`artifacts/model_bundle.joblib`) — never hardcoded in the API layer.
- Consumers should log `model_version` alongside predictions to support
  auditability if the underlying model is retrained/redeployed.

## Important usage notes

- This API returns a **behavioural probability estimate**, not a
  diagnosis. Do not present `risk_level` as a clinical or psychological
  assessment to end users.
- `top_features` describes **association**, not causation. Phrasing is
  deliberately non-causal ("is increasing/decreasing the estimated risk"
  rather than "causes").
- Always use the threshold and version shipped with the current model
  artifact if you need a binary decision rather than a probability —
  see `docs/EVALUATION.md` for why hardcoding a threshold is unsafe
  across model versions.
